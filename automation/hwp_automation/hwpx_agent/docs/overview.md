# 프로젝트 개요

## 이 폴더의 목적

`hwpx_agent`는 HWPX 문서를 한 번에 다 고치는 도구가 아니라, 문서를 안전하게 분해하고 다시 조립할 수 있는 기반을 만드는 폴더입니다.

초보자 기준으로는 `run_pipeline.py`를 먼저 쓰는 것이 가장 쉽습니다. 이 경로는 자산화, 교정 이슈 생성, 리뷰 샘플 생성, 기본 검증까지를 한 번에 수행합니다.

핵심 목표는 아래 4가지입니다.

- HWPX를 텍스트, 표, 이미지, 페이지 정보로 분해
- 분해한 결과를 AI가 다루기 쉬운 자산 구조로 저장
- 교정 결과를 원본 위치와 연결
- 선택한 수정안을 다시 HWPX에 반영

## 현재까지 된 것

- HWPX 패키지 인벤토리 추출
- 본문 문단 자산화
- 표 자산화
- 표 셀 자산화
- 이미지 바이너리와 이미지 배치 자산화
- 페이지 정합성 개선
- 컨테이너 문단과 각주 문단 분류
- 교정 이슈와 `origin_id` 연결
- 검토 파일 생성
- rebuild plan 생성
- 안전한 문단 복원
- 안전한 표 셀 복원

## 현재 검증 완료 범위

테스트 파일 `2023_mei_workforce.hwpx` 기준으로 아래가 실제 확인됐습니다.

- 페이지 수 `239` 정합
- `origin_type=table_cell` 이슈 생성
- rebuilt HWPX 한글에서 정상 열림
- 선택한 표 셀 수정 반영

## 현재 지원 범위

- 본문 텍스트 문단
- 안전한 텍스트 표 셀
- 페이지 번호 추적
- 원본 XML 위치 추적
- 선택 수정안 기반 복원

## 현재 제한 범위

- 그림과 복합 컨트롤이 섞인 문단 자동 수정
- 복잡한 표 셀 자동 수정
- 머리말, 꼬리말, 마스터페이지 수정 복원
- 서식까지 100% 동일한 완전 재생성

## 실무적으로 이해하면 좋은 점

지금 단계는 "AI가 문서를 멋대로 바꾸는 단계"가 아니라 "문서를 안전하게 쪼개고, 어디를 바꿀지 추적하고, 다시 넣을 수 있는 단계"입니다.

즉, 현재는 아래 흐름이 안정화된 상태입니다.

1. 문서를 자산으로 분해한다.
2. 수정 후보를 구조화한다.
3. 사람이 선택한다.
4. 선택한 것만 다시 넣는다.

이 구조가 잡혀 있어야 이후에 맞춤법, 규칙 검사, 품질 관리, 다중 문서 처리로 확장하기 쉽습니다.
